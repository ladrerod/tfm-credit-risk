\title{PD24: producto predictivo de probabilidad de impago a 24 meses}
\author{Daniel Ladrero Meca}
\date{2026}

\begin{document}
\maketitle

\begin{abstract}
PD24 responde a una pregunta acotada: si cinco variables disponibles en la
originación bastan para ordenar el riesgo de impago hipotecario a 24 meses y
entregar el resultado como un producto local verificable. El estudio usa un
compacto de 999.965 préstamos Freddie Mac de 2004--2023, compara históricamente
regresión logística e HistGradientBoosting (HGB), selecciona la alternativa más
parsimoniosa y la encapsula en un bundle versionado servido mediante una API
JSON y una interfaz local Gradio. En el holdout de 2023, la regresión alcanza
AUC 0,773358 y KS 0,400860,
pero incumple la guarda de intercepto de calibración. El resultado acredita
discriminación y un producto académico funcional; no acredita una probabilidad
absoluta estable ni un sistema de decisión crediticia.
\end{abstract}

\section{Resumen ejecutivo}

\textbf{Pregunta de investigación.} ¿Puede un contrato de sólo cinco variables
de originación conservar una capacidad predictiva útil para el impago a 24
meses y convertirse en software local reproducible, sin transformarse en un
sistema de concesión? La respuesta obtenida es afirmativa para la ordenación
del riesgo y la demostración técnica, pero no para la estabilidad de la
probabilidad absoluta.

El objetivo general es recorrer un ciclo de ciencia de datos completo y
auditable. Los objetivos específicos son: (i) definir una etiqueta binaria y
una población temporalmente madura; (ii) seleccionar el menor contrato de
entrada que conserve señal; (iii) comparar una familia lineal interpretable con
un challenger no lineal; (iv) medir discriminación, calibración y estabilidad;
y (v) entregar el modelo como un artefacto versionado accesible por API y por
un formulario local, cubierto por pruebas.

La solución recibe FICO, DTI, CLTV, tipo de interés y número de prestatarios,
aplica una regresión logística calibrada y devuelve un score y una banda de
riesgo. El flujo completo es datos locales, entrenamiento, bundle versionado,
función común de scoring, API e interfaz local y validación automática. Los
criterios de éxito no incluyen una tasa
de aprobación: exigen reproducibilidad, ausencia de fuga temporal, capacidad de
ordenación suficiente, evaluación explícita de calibración y un contrato de
software estricto.

La evidencia principal es doble. Primero, cinco variables conservan la
capacidad predictiva frente al contrato histórico de dieciocho entradas y HGB
no mejora de forma suficiente la discriminación. Segundo, el modelo final
mantiene capacidad de ordenación en 2023, pero su intercepto de calibración
(-0,654081) queda fuera de la guarda [-0,5; 0,5]. Por tanto, PD24 es defendible
como producto predictivo académico y demostración de programación, análisis de
datos y aprendizaje automático, pero no como motor de aprobación, precio,
provisión o capital.

\section{Contexto, objetivo y alcance}

El objetivo general es recorrer de forma trazable el ciclo de un problema de
clasificación: definición del evento, diseño temporal, selección de variables,
comparación de modelos, evaluación y productivización. Este enfoque responde a
las exigencias de análisis, interpretación, reproducibilidad y orientación
profesional de la guía del TFM \cite{guia-tfm}. La aportación no es crear una
plataforma financiera completa, sino demostrar que un modelo pequeño puede
entrenarse, congelarse, probarse y consumirse como software.

El alcance termina en una PD a 24 meses. El score ordena riesgo relativo dentro
de la población estudiada y la banda resume ese orden. No aprueba ni deniega
préstamos, no explica causalmente un caso individual y no estima pérdida
esperada. EAD y LGD sólo serían necesarias si el objetivo futuro fuese calcular
esa pérdida; no son variables ausentes del problema predictivo actual.

En este documento, \emph{PD24} significa probabilidad estimada del evento
definido durante los 24 meses posteriores al primer pago. No significa una
puntuación crediticia comercial, un rating regulatorio ni una regla de corte.
La utilidad académica consiste en demostrar cómo se traduce una pregunta de
clasificación en evidencia cuantitativa y, después, en un componente de
software consumible. La utilidad práctica queda limitada a comparar riesgo
relativo dentro de una población compatible con la estudiada.

La población de Freddie Mac contiene préstamos ya originados. Por tanto, el
modelo no observa solicitudes rechazadas y no debe generalizarse a toda la
población solicitante. Tampoco se ha demostrado transportabilidad a otras
carteras, países o tipos de crédito. Este posible sesgo de selección se mantiene
visible porque una buena métrica interna no corrige por sí sola una diferencia
de población.

Quedan expresamente fuera la política de admisión, el precio, la pérdida
esperada, la exposición, la severidad, los escenarios macroeconómicos, la
contabilidad y el capital. Una evolución a pérdida esperada exigiría construir
y validar por separado EAD y LGD, además de redefinir el caso de uso. Añadirlos
ahora ampliaría el problema sin mejorar la demostración de programación,
análisis del dato y modelización que constituye el núcleo del TFM.

\section{Datos y definición del problema predictivo}

\subsection{Población, grano y muestreo}

La fuente es el Single-Family Loan-Level Dataset de Freddie Mac. La unidad de
análisis es un préstamo hipotecario originado y cada fila conserva sólo el año y
trimestre de cohorte, cinco atributos de originación, la fecha de disponibilidad
de la etiqueta y el resultado binario. El compacto local contiene 999.965 filas
de 2004--2023, nueve columnas y 15.154 eventos (1,515453\%). No contiene
identificadores de préstamo o prestatario.

Se aplicó un límite próximo a 50.000 filas por cohorte anual: los años
2004--2021 contienen 50.000 observaciones, 2022 contiene 49.999 y 2023, 49.966.
Esta decisión controla el tamaño y evita que un año domine por volumen, pero
también impide interpretar la tasa total como prevalencia de la cartera
completa. La muestra pondera casi por igual vintages con tasas muy distintas y
no es una fotografía automática del mercado hipotecario.

\begin{figure}[H]
\centering
\includegraphics[width=\linewidth]{figures/eda_population_quality.png}
\caption{Estructura temporal, desequilibrio y completitud del compacto final.}
\end{figure}

La prevalencia anual va del 0,380\% en 2015 al 4,826\% en 2007. Esa variación
justifica la validación temporal: una partición aleatoria mezclaría regímenes y
podría ofrecer una visión demasiado optimista de la generalización. El año 2020
se identifica en las figuras y resultados como periodo excepcional, pero el
TFM no atribuye sus valores a una causa concreta ni usa esa cohorte para
seleccionar o calibrar el modelo.

La población sólo incluye préstamos originados y observados por Freddie Mac. No
incluye solicitudes rechazadas, de modo que existe un posible sesgo de selección
y no se infiere comportamiento fuera de esta población. Se localizaron 1.455
filas adicionales con los nueve campos idénticos (0,146\%); al haber retirado
los identificadores, no es posible distinguir préstamos distintos con iguales
atributos de duplicados de origen. Se documenta la incertidumbre y no se eliminan
filas sin evidencia suficiente.

\subsection{Etiqueta, horizonte y madurez}

La etiqueta \texttt{default\_24m} vale uno cuando aparece la primera mora de 90
o más días o un código de baja crediticia 02, 03, 09 o 15 dentro de los 24 meses
posteriores al primer pago. El horizonte es fijo para todas las cohortes y no se
mezcla con estados mensuales, prepago o severidad de pérdida.

\texttt{pd\_label\_available\_date} representa la primera fecha en que esos 24
meses están observados. El compacto no contiene etiquetas ausentes y sólo acepta
cero o uno; la fecha de disponibilidad abarca desde 2006-01-01 hasta 2026-03-01.
Para el ajuste final se exige además que sea estrictamente anterior a
2020-03-01. El código valida esquema, dominio y madurez, pero recibe la etiqueta
ya construida: la derivación desde los ficheros mensuales originales no forma
parte del producto reducido y se declara como límite de reproducción.

\subsection{Calidad y señal descriptiva de las cinco entradas}

Las entradas son conocidas en originación. En el compacto completo, la ausencia
más relevante es DTI (89.077 filas; 8,908\%); FICO, CLTV y número de
prestatarios tienen menos del 0,04\% y el tipo de interés no tiene ausencias. El
promedio global oculta un cambio temporal importante: DTI falta en el 24,344\%
del desarrollo 2010--2015, en el 4,279\% de calibración 2016--2017 y sólo en el
0,006\% de 2023. Por ello la ausencia puede actuar como marcador de vintage o de
proceso, no sólo como un dato accidental. El pipeline imputa la mediana y añade
un indicador de ausencia; en la interpretación no se atribuye causalidad a ese
indicador.

\begin{figure}[H]
\centering
\includegraphics[width=\linewidth]{figures/eda_feature_gradients.png}
\caption{Tasas univariantes por quintil en desarrollo 2010--2015. Los empates
pueden producir grupos de distinto tamaño; no son efectos causales.}
\end{figure}

Las asociaciones descriptivas apoyan el contrato reducido. Entre los extremos
de los quintiles, la tasa baja del 1,447\% al 0,102\% al aumentar FICO; sube del
0,069\% al 0,458\% con DTI, del 0,162\% al 1,563\% con CLTV y del 0,143\% al
1,268\% con el tipo. Los préstamos con un prestatario presentan 0,746\% frente
a 0,322\% con dos. Estas comparaciones se realizan antes del modelo
multivariante, excluyen ausentes sólo para construir cada gráfico y no bastan
para justificar una decisión individual.

El desarrollo contiene únicamente uno o dos prestatarios, mientras que en 2023
hay 871 filas con tres a cinco (1,743\%). El endpoint conserva el rango visto en
desarrollo y rechaza esos valores; la evaluación retrospectiva, en cambio, los
incluye y muestra el límite de soporte del contrato. La diferencia debe
considerarse si el producto se extiende a nuevas poblaciones.

Las comprobaciones de tipo, rango, completitud y forma siguen el tratamiento de
datos impartido en el máster \cite{data-prep}. Los términos de Freddie Mac
permiten publicar resultados académicos y derivados no comerciales bajo sus
condiciones, pero no redistribuir datos de forma que se reconstruya el dataset o
se identifique a personas \cite{freddie-terms}. Por prudencia, compacto y bundle
permanecen locales; el repositorio contiene código y agregados. Esta descripción
no constituye asesoramiento jurídico y los controles no eliminan la advertencia
de la fuente sobre posibles errores u omisiones.

\section{Diseño experimental y selección de variables}

\subsection{Particiones temporales}

La evaluación imita un uso futuro: el modelo sólo aprende de cohortes anteriores
a las que evalúa. La selección histórica utiliza tres folds. Para el fold 2015
se desarrolla con 2004--2009, se calibra con 2010--2011 y se embargan
2012--2014; los folds 2016 y 2017 desplazan cada bloque un año. El embargo deja
transcurrir el horizonte de 24 meses y reduce el riesgo de que una etiqueta aún
no madura intervenga en una decisión de modelado.

\begin{center}\small
\begin{tabular}{l p{0.14\linewidth} p{0.14\linewidth} p{0.15\linewidth} p{0.27\linewidth}}
\textbf{Fase} & \textbf{Cohortes} & \textbf{Resultado} & \textbf{Acceso a etiqueta} & \textbf{Uso permitido}\\ \hline
Desarrollo final & 2010--2015 & 300.000 filas & $<$ 2020-03-01 & Imputación, escalado y coeficientes\\
Calibración & 2016--2017 & 99.920 filas & $<$ 2020-03-01 & Sigmoide y cortes P50/P90\\
Pre-holdout & 2018--2022 & Por año y agregado & Sólo después de congelar ajuste & Evaluación; nunca reentrenamiento\\
Periodo excepcional & 2020 & Resultado separado & Igual que pre-holdout & Diagnóstico, no selección\\
Holdout & 2023 & 49.966 filas & Apertura final & Estimación final sin reajuste\\
\end{tabular}
\end{center}

El modelo final se ajusta con 2010--2015, se calibra con 2016--2017, se observa
por año en 2018--2022 y reserva 2023 como holdout. La fecha de etiqueta debe ser
estrictamente anterior a 2020-03-01 para cualquier fila de ajuste. El año 2020
se reporta como periodo excepcional y no gobierna selección, calibración ni
reajuste. Esta decisión no supone que 2020 sea irrelevante: evita basar el modelo
en un único régimen difícil de generalizar.

Estos controles demuestran la separación impuesta por el programa. No pueden

declara como supuesto de trabajo.

\subsection{Selección del contrato de cinco entradas}

La comparación entre cinco y dieciocho variables aplica una regla pareada: para
ampliar el contrato se exigían al menos dos folds con mejora de AUC de 0,01 y
mejora relativa de Brier o log-loss del 5\%, sin deterioro material en ningún
fold. Las diferencias de AUC del modelo de dieciocho entradas frente al de cinco
fueron -0,031352, +0,000793 y -0,013689. La ampliación no superó la regla y se
conservaron las cinco entradas.

\begin{center}\small
\begin{tabular}{p{0.24\linewidth} p{0.25\linewidth} p{0.40\linewidth}}
\textbf{Entrada} & \textbf{Qué resume} & \textbf{Motivo de permanencia}\\ \hline
\texttt{origination\_fico} & Historial crediticio resumido & Mayor aportación en ablación y gradiente descriptivo más claro\\
\texttt{original\_dti} & Deuda respecto a ingresos & Señal incremental y ausencia informativa tratada explícitamente\\
\texttt{original\_cltv} & Apalancamiento sobre la garantía & Señal fuerte en el tramo alto y evita duplicar LTV\\
\texttt{original\_interest\_rate} & Condiciones originales del préstamo & Mejora probabilística histórica con un campo numérico disponible\\
\texttt{number\_of\_borrowers} & Estructura conjunta del préstamo & Aportación estable y contrato sencillo de explicar\\
\end{tabular}
\end{center}

La ablación refuerza que FICO aporta la mayor señal: al retirarlo, el AUC macro
baja de 0,815065 a 0,747310. Al retirar por separado las demás variables, el AUC
queda entre 0,796718 y 0,807096. Esto mide asociación predictiva agregada, no
causalidad. La selección de variables y la regresión logística se apoyan en los
materiales docentes correspondientes \cite{seleccion,logistica}.

\begin{figure}[htbp]
\centering
\includegraphics[width=\linewidth,trim=0 18pt 0 0,clip]{figures/fold_model_comparison.png}
\caption{Comparación temporal de contratos y familias durante la selección.}

Las trece entradas descartadas se agrupan por una razón defendible. LTV y los
campos de seguro hipotecario duplicaban en parte la información de CLTV; plazo,
tipo de amortización, número de unidades y bandera de alto saldo tenían poca
variación; finalidad, ocupación, tipo y estado del inmueble añadían categorías,
tratamiento de desconocidos y riesgo territorial sin una mejora estable; y el
saldo original introducía tamaño monetario sin ser necesario para estimar esta
PD. Las variables macroeconómicas exigían otra fuente, fecha, actualización y
una narrativa causal que no pertenece al producto mínimo. El descarte no afirma
que esas variables nunca puedan aportar señal, sino que no superaron la puerta
definida para justificar un contrato más complejo.

La evidencia de selección 5 frente a 18 y la comparación con HGB se conserva
como resultado histórico congelado en la memoria y en sus figuras. El entregable
ejecutable se simplificó después al producto final de cinco variables: ya no
incluye el compacto ancho ni los programas de aquella experimentación. Por ello
la predicción final sí es reproducible, mientras que esa fase comparativa no es
recalculable desde el repositorio reducido. Explicitarlo evita presentar como
reproducible una evidencia que hoy sólo es auditable en el documento.

\section{Modelos predictivos}

\subsection{Regresión logística implementada}

La familia seleccionada modela el log-odds del evento como una combinación
lineal de las entradas transformadas. Si $\widetilde{x}_{ik}$ representa cada
columna tras imputación, indicadores de ausencia y estandarización, el estimador
base calcula:

\[
\eta_i=\beta_0+\sum_{k=1}^{K}\beta_k\widetilde{x}_{ik},
\qquad
p_i^{\mathrm{raw}}=\frac{1}{1+\exp(-\eta_i)}.
\]

El contrato público mantiene cinco valores, pero el diseño interno tiene
$K=8$: a las cinco variables se añaden indicadores de ausencia para FICO, DTI y
CLTV, que presentaban algún nulo en desarrollo. Esto evita confundir ``cinco
entradas'' con ``cinco coeficientes''. La imputación usa la mediana aprendida en
2010--2015; después, \texttt{StandardScaler} centra y escala las columnas, y
\texttt{LogisticRegression} usa $C=1$, solver L-BFGS, un máximo de 500
iteraciones y semilla 20260819.

La clase positiva es poco frecuente. \texttt{class\_weight=balanced} aumenta su
peso durante el ajuste para que el optimizador no ignore los eventos, pero
también aleja la salida bruta de la prevalencia observada. Por eso se reserva
2016--2017 para una calibración sigmoide independiente:

\[
p_i^{\mathrm{cal}}
=\sigma\!\left(\alpha+\gamma\,\mathrm{logit}
  (p_i^{\mathrm{raw}})\right),
\qquad \sigma(t)=\frac{1}{1+e^{-t}}.
\]

El calibrador no vuelve a estimar las cinco relaciones principales: aprende
sólo un intercepto y una pendiente sobre el logit bruto. Esta separación permite
corregir el nivel probabilístico sin usar los periodos de evaluación. Los
materiales de regresión logística del máster respaldan el logit, la estimación y
la lectura de coeficientes \cite{logistica}; la calibración separada es una
decisión técnica del producto.

\subsection{Challenger histórico HistGradientBoosting}

Los dos candidatos históricos usan el mismo contrato de cinco entradas para que
la comparación mida la familia y no un cambio de información. HGB utiliza
imputación por mediana e indicadores, ponderación balanceada, tasa de
aprendizaje 0,05, 150 iteraciones, 15 hojas, 40 observaciones mínimas por hoja y
regularización L2 igual a uno. Puede representar interacciones y relaciones no
lineales sin especificarlas, pero es menos transparente y añade complejidad de
explicación. Árboles y clasificadores forman parte del temario
\cite{clasificadores}; este ajuste concreto pertenece al TFM.

\begin{center}\small
\begin{tabular}{l r r r p{0.27\linewidth}}
\textbf{Modelo} & \textbf{AUC} & \textbf{Brier} & \textbf{log-loss} & \textbf{Lectura}\\ \hline
Logística & 0,815065 & 0,005930 & 0,033673 & Mayor discriminación y explicación directa\\
HGB & 0,800760 & 0,005888 & 0,033005 & Menor error probabilístico, pero no victoria material\\
\end{tabular}
\end{center}

En los folds de selección, la logística obtiene AUC macro 0,815065, Brier
0,005930 y log-loss 0,033673; HGB obtiene 0,800760, 0,005888 y 0,033005. HGB
reduce ligeramente los errores probabilísticos, pero pierde AUC y no supera la
regla de sustitución. Se elige la regresión logística por discriminación,
estabilidad operativa, interpretabilidad agregada y parsimonia.

Esta comparación se conserva como evidencia histórica congelada. El código
final ya no contiene HGB ni un selector automático; añadirlos de nuevo sólo para
mostrar más código contradiría el objetivo de simplificación y no haría el
producto más defendible.

\subsection{Calibración y definición de bandas}

La calibración 2016--2017 contiene 99.920 observaciones y 708 eventos: AUC
0,798864, PR-AUC 0,032190, KS 0,447723, Brier 0,006965, log-loss 0,037717,
intercepto -0,170426 y pendiente 0,963033. Los percentiles 50 y 90 del score
calibrado fijan los cortes de banda en 0,003899719891 y 0,015918064398. Esos
cortes ordenan la población; no convierten por sí solos el score en una
probabilidad contractual.

La banda baja corresponde a scores inferiores al P50 de calibración; la media,
al intervalo $[P50,P90)$; y la alta, a valores iguales o superiores al P90.
Estos cuantiles permiten resumir el ranking sin fijar un umbral de aceptación.
Si cambia la distribución del score, las proporciones futuras por banda dejan
de ser 50/40/10, como ocurre en 2023. El nombre \texttt{risk\_score} representa
la probabilidad estimada tras calibración, no una escala de puntos ni una
decisión.

\section{Resultados, estabilidad e interpretabilidad}

\subsection{Qué mide cada indicador}

La evaluación se presenta por cohorte para no ocultar cambios temporales. No
existe una métrica única que demuestre que el modelo sea bueno para cualquier
uso: discriminación y calibración responden a preguntas diferentes.

\begin{center}\small
\begin{tabular}{p{0.16\linewidth} p{0.38\linewidth} p{0.12\linewidth} p{0.24\linewidth}}
\textbf{Indicador} & \textbf{Pregunta que responde} & \textbf{Mejor valor} & \textbf{Precaución}\\ \hline
ROC-AUC & ¿Ordena por encima un evento frente a un no evento? & 1 & No mide nivel probabilístico\\
PR-AUC & ¿Concentra eventos al priorizar scores altos? & 1 & Depende de la prevalencia\\
KS & ¿Cuál es la máxima separación entre distribuciones acumuladas? & 1 & Resume un solo punto de separación\\
Brier & ¿Cuál es el error cuadrático medio de la probabilidad? & 0 & Cambia con la tasa base\\
log-loss & ¿Penaliza especialmente probabilidades seguras y erróneas? & 0 & Muy sensible a extremos\\
Intercepto & ¿Hay sesgo medio en el nivel estimado? & 0 & Es diagnóstico, no corrección automática\\
Pendiente & ¿Es adecuada la dispersión del score? & 1 & $<1$ suele indicar exceso de extremos\\
PSI & ¿Cambió una distribución respecto a referencia? & 0 & No utiliza el resultado ni mide AUC\\
\end{tabular}
\end{center}

Con clases muy desequilibradas, PR-AUC complementa a ROC-AUC porque se centra
en la precisión y exhaustividad de la clase minoritaria \cite{saito}. En 2023,
su referencia ingenua es aproximadamente la prevalencia 0,017152, mientras que
el modelo alcanza 0,060227. Brier resume el error cuadrático de las
probabilidades \cite{brier}; log-loss penaliza con más intensidad una
probabilidad extrema asignada al resultado equivocado. Las guardas de
intercepto $[-0,5;0,5]$ y pendiente $[0,8;1,2]$ son decisiones explícitas del

\subsection{Interpretabilidad agregada}

Los coeficientes estandarizados son FICO -0,774665, DTI 0,368087, CLTV
0,517045, tipo 0,470748 y número de prestatarios -0,498650. Sus signos son
coherentes con asociaciones agregadas del conjunto estudiado, pero no explican
causas ni justifican decisiones individuales. Entre los indicadores de
ausencia, DTI tiene coeficiente 0,410897, mientras que FICO y CLTV quedan cerca
de cero. Esto confirma que el patrón de falta de DTI contiene información en el
periodo de desarrollo y exige cautela ante el cambio temporal de completitud.

Los coeficientes están expresados sobre columnas estandarizadas, de modo que su
magnitud permite comparar influencia dentro del pipeline, no traducir una unidad
original directamente a puntos de score. Tampoco son explicaciones locales: la
respuesta de un préstamo concreto combina las ocho columnas internas y la
calibración posterior.

No se reporta rendimiento ni
deriva cuantitativa para 2024--2026 porque esos datos no forman parte del input
final reproducible. Su incorporación queda como línea futura cuando exista un
extracto retenido, documentado y con madurez suficiente.

\subsection{Del compacto a una predicción}

El producto mínimo adopta el flujo:

\begin{center}
compacto local $\rightarrow$ entrenamiento $\rightarrow$ bundle versionado
$\rightarrow$ scoring común $\rightarrow$ API JSON o interfaz Gradio
$\rightarrow$ PD y banda.
\end{center}

\textbf{Entrenar.} El comando calcula primero el hash del compacto, exige la
cabecera exacta y carga sólo 2010--2017. Tras el corte de madurez, separa
desarrollo y calibración, ajusta el pipeline, fija P50/P90 y crea referencias de
distribución.

\textbf{Guardar.} El artefacto se escribe como
\texttt{pd24-model.joblib.partial} y sólo después se reemplaza el destino con
\texttt{os.replace}. Un fallo previo conserva el bundle anterior y elimina el
parcial. Es un reemplazo atómico en el mismo directorio; no se presenta como
transacción duradera ni como solución para escritores concurrentes.

\textbf{Cargar y validar.} Antes de servir se comprueban identidad, familia,
orden de variables, esquema, periodos, cortes, referencias, métricas y hashes.
La predicción construye un \texttt{DataFrame} en el orden congelado, ejecuta
\texttt{predict\_proba} y asigna la banda con los cortes guardados.
La función \texttt{score\_product} concentra estos pasos y es reutilizada por
la API y el formulario, evitando dos implementaciones del mismo contrato.

El bundle \texttt{five-variable-pd-2} conserva pipeline, calibrador, orden y
rangos de variables, cortes, versión y hashes. Sus 18 claves se agrupan así:

\subsection{API e interfaz local en la frontera del producto}

La API Flask expone \texttt{GET /health} y \texttt{POST /predict} en
\texttt{127.0.0.1:5000}. El diseño usa HTTP, REST y JSON del módulo de
productivización \cite{productivizacion}. Como acceso visual, una
\texttt{gr.Interface} recibe las cinco variables numéricas y devuelve PD en
porcentaje, banda y advertencia académica. Esta forma de demostración mediante
componentes de entrada y salida aparece en los materiales del máster
\cite{gradio}.

Ambas vías llaman a la misma función \texttt{score\_product}; así, el orden de
variables, los rangos, la probabilidad y los cortes no se duplican. La interfaz
se limita a Python y Gradio: no incorpora HTML, CSS o JavaScript escritos a
mano, persistencia, base de datos, autenticación, contenedores, nube u
observabilidad.

No existe una ruta \texttt{/}; por eso abrir \texttt{http://127.0.0.1:5000/}
en el navegador devuelve 404 de forma esperada. La comprobación operativa se
realiza en \texttt{/health} y la predicción mediante un \texttt{POST} JSON a
\texttt{/predict}. El formulario visual se abre por separado en
\texttt{http://127.0.0.1:7860/}. Flask y Gradio usan servidores de desarrollo,
suficientes para la demostración local pero no presentados como despliegue
productivo real.

\section{Conclusiones, limitaciones y líneas futuras}

\subsection{Respuesta a la pregunta de investigación}

Sí: dentro de la muestra estudiada, cinco variables disponibles en originación
conservan capacidad suficiente para ordenar el riesgo a 24 meses y pueden
entregarse como un producto local reproducible. La regresión logística supera a
HGB en AUC macro durante la comparación histórica, alcanza AUC 0,773358 y KS
0,400860 en 2023, y produce bandas con tasas observadas crecientes. El pipeline,
el bundle, la API, la interfaz Gradio y treinta y cuatro pruebas completan la
demostración de software.

La respuesta tiene una condición decisiva: el intercepto de calibración 2023 es
-0,654081 y las probabilidades medias superan las incidencias observadas en las
tres bandas. Por tanto, el resultado demuestra ranking y productivización, no
una PD absoluta estable ni aptitud para decidir una concesión.

\begin{center}\small
\begin{tabular}{p{0.28\linewidth} p{0.28\linewidth} p{0.33\linewidth}}
\textbf{Demostrado} & \textbf{No demostrado} & \textbf{Mejora necesaria}\\ \hline
Señal predictiva de cinco entradas & Generalización a solicitantes rechazados & Validación en población objetivo\\
Ordenación temporal en 2023 & Probabilidad absoluta estable & Recalibración en cohorte posterior\\
Bandas con orden observado & Tamaño estable de las bandas & Revisar cortes P50/P90\\
Entrenamiento y evaluación reproducibles & Reconstrucción mensual de etiqueta & Manifiesto o proceso de origen separado\\
API e interfaz locales validadas & Servicio productivo multiusuario & Infraestructura sólo si surge ese uso\\
\end{tabular}
\end{center}

\subsection{Limitaciones}

Las limitaciones principales son la muestra académica, la ausencia del proceso
crudo de construcción de etiqueta en el entregable, la evidencia histórica no
recalculable de selección, el cambio temporal de distribuciones y el carácter
local de la API y de la interfaz. Tampoco se evalúan sesgo individual, causalidad o desempeño en
otras carteras. Usos excluidos: aprobación o denegación, pricing, provisiones,
capital regulatorio y decisiones automáticas.

La tasa de evento varía mucho por cohorte y desarrollo pertenece a un periodo de
baja incidencia. DTI cambia de completitud, aparecen valores de número de
prestatarios fuera del soporte de entrenamiento y el PSI actual de esa variable
no detecta nuevas categorías. También existen filas indistinguibles sin
identificador cuya naturaleza no puede determinarse. Estas observaciones no
anulan el ranking publicado, pero delimitan la transportabilidad y la lectura de
estabilidad.

\subsection{Líneas futuras priorizadas}

Las mejoras razonables son recalibrar con una cohorte posterior independiente,
revalidar los cortes de banda, añadir seguimiento futuro cuando las etiquetas
sean maduras y conservar un manifiesto verificable de los datos fuente. Sólo si
el objetivo evolucionara a pérdida esperada se añadirían modelos separados de
EAD y LGD. Esas ampliaciones no son necesarias para defender el producto PD24
actual.

La prioridad no es añadir más algoritmos. Primero debe comprobarse si una
recalibración corrige el nivel sin degradar el ranking; después, ampliar de forma
deliberada el rango de prestatarios o rechazar esa población; y finalmente
repetir la evaluación con cohortes nuevas y maduras. Sólo una necesidad real de
servicio multiusuario justificaría sustituir el servidor de desarrollo, añadir
autenticación u operar el producto fuera de un entorno local.

\textbf{E.3. Validación y scoring compartido} (\path{src/product.py})

{\scriptsize\begin{verbatim}
def score_product(bundle, payload):
    features = bundle["features"]
    if (not isinstance(features, list)
            or not isinstance(payload, Mapping)
            or set(payload) != set(features)):
        raise ValueError("invalid input")
    schema = bundle["input_schema"]
    for name in features:
        value = payload[name]
        if (type(value) not in (int, float)
                or (type(value) is float
                    and not math.isfinite(value))):
            raise ValueError("invalid input")
        limits = schema[name]
        if value < limits["minimum"] or value > limits["maximum"]:
            raise ValueError("invalid input")
    frame = pd.DataFrame([payload], columns=features)
    score = float(bundle["model"].predict_proba(frame)[0, 1])
    if not math.isfinite(score) or not 0 <= score <= 1:
        raise RuntimeError("model returned an invalid probability")
    p50, p90 = bundle["risk_band_cutoffs"]
    band = (
        "low" if score < p50
        else "medium" if score < p90
        else "high"
    )
    return score, band
\end{verbatim}}
